# WolOS design

Wonderland theme: four nested doors, the small door into Wonderland with light coming through. One accent: violet `#7C5CFF` (dark `#8B6CFF`, as in `tokens/colors.json`). WolOS neutrals (a faint violet hue).

GTK render check: GTK 4 draws SVG icons with its own renderer, and some filter chains librsvg draws right come out there as grey or dark blocks. `bash design/tools/icons/gtkcheck/check.sh [svg ...]` compiles `gtkcheck.c` (cc + the gtk4 headers), starts a private `gtk4-broadwayd`, draws every full-colour icon (`icons/apps`, `apps/small`, places, devices, mimetypes) through `GtkIconPaintable` and the cairo renderer, and fails when the RMSE against the `rsvg-convert` render of the same size is above 0.02 at 48 or 128 px (premultiplied RGBA, `GTKCHECK_RMSE` overrides). Without one of its tools it prints `SKIPPED: ...` and exits 77. The shell test `icons_v2::gtk_draws_every_full_colour_icon_like_librsvg` runs it (so it runs on the forge with the rest of the tests) and prints a `*** SKIPPED ... ***` line when it cannot. Arch lane: `.claude/bin/local-lane.sh run 'bash design/tools/icons/gtkcheck/check.sh'`. Known traps, handled by the generator: (1) GTK sizes a filter's source from the geometry of what is filtered, so a thin stroke (a bare stem) or an offset copy collapses it and the shadow floods a block: `svgk.gtk_safe` (run by `Cv.svg` and, for the Type A2 icons, by `tools/icons/a2.py`) draws every filtered element inside a group that opens with `svgk.PAD`, a canvas-sized rect with no pixels, moving the element's transform, clip-path, mask and opacity to an outer group; (2) GTK has no lighting primitives (`feSpecularLighting`, `feDiffuseLighting` draw black): the settings gear's bevel is a colour matrix, a white wash and a shifted-alpha shade; (3) GTK and librsvg blur a thin stroke differently at icon sizes: a soft ring is `svgk.soft_ring`, a radial gradient. The Type A2 icons get the same pass (`tools/icons/a2.py`); measured when it was added (76 files changed, wrapper only): librsvg renders the old and new files with RMSE 0 at 48 px, at most 0.0019 at 128 px, and at most 0.0065 at 512 px, above 0.002 on two icons only (`user-trash` 0.0065, where the old filter region clipped the blur on a 63-pixel row and the wrapped file does not; `apps/wolos-text-editor` 0.0023); gtkcheck on the Arch lane: 103 icons, worst GTK-versus-librsvg RMSE 0.0145 (0.0146 before). `gtkcheck/known-failures.txt` lists icons still allowed to fail (empty now; a listed icon that passes is an error). Filters are allowed in the full-colour sets only because gtkcheck proves GTK draws them like librsvg; outside them (symbolic, store) no icon uses a filter (`icons_v2::icons_outside_the_full_colour_sets_have_no_filter`). A renderer that ignores filters must still draw each icon: `icons_v2::full_colour_icons_read_with_their_filters_ignored` renders it with its `filter` attributes removed and fails above RMSE 0.08 at 48 or 128 px; `FILTER_ONLY_KNOWN` there lists icons still allowed to fail (empty; paper grain is `svgk.grained`, an invisible shape whose noise is clipped to it).
Install icons: `sh design/icons/install.sh [dest]` (copies SVGs, symlinks aliases like `firefox`, `utilities-terminal`, `org.gnome.Nautilus`, runs `gtk-update-icon-cache`).
Tokens: source `colors.sh` (`WOL_THEME=dark` selects dark), import `colors.css` in GTK/Waybar/swaync CSS.
Fonts (ports): `x11-fonts/inter`, `x11-fonts/jetbrains-mono`, `x11-fonts/noto-basic`.
Brand and the rabbit are generated (`tools/gen.py` and `tools/illus/build.py` call the same code): `python3 -I design/tools/brand/build.py design [site-drop dir]` (stdlib, plus `rsvg-convert`); every drawing is fill-only (strokes are expanded to outlines by `tools/brand/outline.py`).
Rules: SVG only (except `brand/wolos-splash.png`, `brand/wolos-splash-ja.png`, `brand/os_wolos.png`, the illustration PNGs and the PNGs `tools/icons.py` renders); every icon comes from `python3 tools/icons.py [--sheet out.png]`; symbolic icons are fill-only `currentColor` (GTK recolors them for light and dark).
